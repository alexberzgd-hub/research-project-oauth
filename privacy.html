Research Project Codex · Редакция от 9 ноября 2026 года

1. Приложение и оператор

Research Project Codex предназначено для управления личным исследовательским проектом: задачами, документами, источниками и результатами. Оператор — владелец проекта. Контакт по вопросам данных и доступа: alexberzgd@gmail.com.

2. Какие данные используются

После разрешения пользователя приложение может получать идентификаторы, имена, типы, структуру папок, даты изменения и сведения о доступе к файлам Google Drive, а также содержимое выбранных документов, таблиц и загружаемых файлов. Объём чтения и изменений определяется выполняемым заданием.

Google OAuth используется для авторизации. Приложению необходимы данные OAuth-клиента и refresh token для обновления краткосрочного access token. Пароль Google-аккаунта приложение не запрашивает.

3. Для чего нужны данные

Данные используются для навигации по проекту, анализа документов по поручению пользователя, подготовки задач и отчётов, создания и изменения согласованных файлов и папок, сохранения результатов, проверки целостности и восстановления работы.

Данные не продаются и не используются оператором для рекламного таргетинга.

4. Облачная обработка и сторонние сервисы

Для выполнения заданий выбранные данные могут обрабатываться в Codex/OpenAI и сохраняться в рабочей облачной среде. Следовательно, обработка не ограничивается Google Drive или локальным компьютером пользователя. Условия обработки и хранения на стороне платформы определяются применимыми условиями сервиса и настройками аккаунта.

Сохранение в GitHub или другом внешнем хранилище выполняется в рамках разрешённого задания. Само разрешение Google OAuth не означает согласия на публичную публикацию документов. Этот информационный сайт GitHub Pages не запрашивает OAuth-токены и не содержит исследовательские файлы проекта.

5. Хранение и защита

Исходные канонические документы остаются на Google Drive. Рабочие копии, экспорты, отчёты, журналы операций и контрольные архивы могут храниться в облачной среде и выбранных владельцем хранилищах столько, сколько они необходимы для задач, восстановления и истории проекта, либо до решения владельца об удалении. Отдельные сервисы и резервные копии могут иметь собственные сроки хранения.

Учётные данные следует хранить в защищённых настройках среды; они не предназначены для публикации в репозиториях, документах, журналах или сообщениях. Доступ ограничивается настройками используемых платформ и предоставленными полномочиями. Абсолютная защищённость передачи и хранения не гарантируется.

6. Отзыв доступа и удаление

Пользователь может отозвать доступ Research Project Codex в настройках подключений Google-аккаунта. После отзыва новые обращения с отозванным разрешением становятся недоступны; для продолжения требуется новая авторизация.

Отзыв доступа не удаляет ранее созданные копии и документы. Для удаления подконтрольных оператору рабочих копий и учётных данных нужно обратиться по контактному email. Исходные файлы Google Drive удаляются владельцем отдельно. Удаление данных и резервных копий на стороне сторонней платформы выполняется по её процедурам.

7. Правила Google API

Оператор обязуется использовать и передавать данные, полученные через Google API, в соответствии с Google API Services User Data Policy, включая требования Limited Use. Эта политика не является заявлением о прохождении проверки Google или подтверждением технической сертификации приложения.

8. Информационный сайт

На этих двух страницах нет собственных аналитических скриптов, рекламных трекеров, форм входа или форм сбора токенов. GitHub как хостинг может обрабатывать технические данные посещений согласно своей политике конфиденциальности.
